### Code navigation

Choose the first substantive discovery action by the requested operation, not just the topic's wording. Reading applicable AGENTS.md instructions, activating the checkout, and checking tool availability are prerequisites, not discovery. For the matching task, use the selected tool before searching with an alternative:

For semantic or structural discovery, start the selected tool at the repository root using its path argument; do not enumerate the source tree to choose a starting directory. Source-tree listings (`ls`, `find`, or `rg --files`) and searches for guessed implementation keywords are substantive discovery, not prerequisites, and must not precede colgrep or ast-grep on their matching routes. Prerequisite reads may inspect applicable instruction files, tool availability, or the specific configuration needed to invoke the tool; keep them focused and do not include source enumeration. A request whose actual goal is literal text or file discovery still starts with `rg`.

- Implementation discovery by meaning when the path and symbol are unknown: start with colgrep semantic discovery, then verify its candidates with focused literal searches or source reads. Use colgrep instead of Serena or `rg` for this initial discovery; a known concept is not a known symbol or literal. This route does not apply to declaration, caller, or reference tracing for a user-named identifier.
- Repeated syntactic shapes or sibling implementation audits expressible as AST patterns: start with ast-grep structural search before regex search. Use ast-grep instead of Serena or `rg` for this initial discovery; knowing one example does not make a syntax audit a literal search. Symbol identity, calls, references, and type relationships remain Serena tasks.
- Known symbols, their definitions/bodies, callers, or references: start with Serena in the selected checkout. A user-named identifier is a known symbol when the request asks to trace its declaration, importing callers, usages, or conditions along its call path; an unknown file location does not make that a semantic discovery task. Locate the named symbol with Serena first, then inspect its references and relevant source bodies rather than rediscovering it with colgrep.
- Known strings, config keys, log text, or file names/paths: start with ripgrep (`rg`); use `rg --files` for file discovery. Literal text and file searches remain `rg` tasks.
- JSON structure, values, or filtering: use jq rather than plain-text search.

On macOS, run Colgrep with explicit subcommands and the repository root: `colgrep search QUERY ROOT` for semantic discovery and `colgrep init ROOT` for initialization. Request execution outside the sandbox (`sandbox_permissions: "require_escalated"` when using `exec_command`) on the first attempt for both commands. The managed `.codex/rules/colgrep.rules` authorizes these prefixes in a trusted repository; it does not select the execution boundary. Keep normal acceleration defaults; do not force CPU to work around sandbox GPU restrictions. Honor an explicit user request for CPU execution. An optional `--force-gpu` check may verify GPU access.

Keep Colgrep's normal automatic incremental index updates enabled on every search. Do not add `--no-update` to regular navigation or rely on a prebuilt index staying current. Controlled evaluation benchmarks may use their own isolated index policy.

If the selected tool fails, is unavailable, or cannot express the task, briefly state the actual reason and use a focused available fallback. Do not perform a token tool call after discovering the answer with the wrong tool. A missing tool affects only its matching route; keep using the other routes. Do not install or bootstrap tools automatically. Install missing tools only through explicitly requested `$s-obvious-dev-setup`.

An empty result is not a tool failure or proof of inapplicability. When the source language is unknown, omit `--lang` initially so ast-grep infers it from file extensions instead of guessing a language that excludes source. Before switching tools after an empty ast-grep result, use `--inspect summary` to distinguish zero scanned files from scanned files with no matches. For zero scanned files, correct path, language, or ignore configuration using tool diagnostics and focused known configuration. For scanned files with no matches, simplify or broaden the AST pattern within the relevant scope. If a valid structural search still yields no matches, report that evidence and explain why a focused source read or literal fallback is needed. Do not use an empty probe to justify doing the initial structural discovery with regex or source enumeration.
