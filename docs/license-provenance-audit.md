# NESweep provenance audit and proposed MIT rewrite boundary

For the later GPLv3 target, use the narrower [retained-code audit](gplv3-retained-code-audit.md) and its symbol/region map. The file-level MIT boundaries below are historical conservative planning, not a finding that every inherited file or line requires replacement.

Audited 2026-10-27. Target: local checkout at `3de40ca6d2fe6574e57e631dcc261b7f3bedcbc7`. This report inventories provenance and proposes engineering boundaries; it does not certify copyright ownership, legal clearance, or a completed MIT conversion. No product source or license has been changed.

## Conclusion

An MIT version appears achievable, but the current extension still contains inherited implementations across the editor, context tracking, prompt construction, response parsing, and configuration/UI. Replacing only the old Sweep schemas or changing the LICENSE file would not address those surfaces.

The strongest preservation candidates are the local MLX server, managed runtime, gRPC protocol/generated bindings, Qwen continuation features, and OpenTelemetry integration introduced during this fork. Their introduction in Aaron-authored commits is evidence of local provenance, not proof that every line is original or independently owned. Preserve these candidates only after checking their inputs and separating them from inherited implementations.

The proposed path preserves existing product capabilities: independently implement the inherited editor/context/model-adapter layers, adapt cleared local runtime code to those new boundaries, replace inherited branding, and recreate inherited tests/documentation. Dropping features is optional, not a prerequisite for MIT.

## Licensing findings

### The cited Zed license rationale is incorrect for the cited revision

At the exact revision cited by this project's README, [`crates/zeta/Cargo.toml`](https://github.com/zed-industries/zed/blob/76167109db7b/crates/zeta/Cargo.toml) declares `GPL-3.0-or-later`. The cited [`sweep_ai.rs`](https://github.com/zed-industries/zed/blob/76167109db7b/crates/zeta/src/sweep_ai.rs) is in that crate. Zed's [open-source announcement](https://zed.dev/blog/zed-is-now-open-source) also distinguishes the GPL editor from AGPL server components.

This contradicts the README's explanation that this source was AGPL simply because it was part of the editor. It does not establish MIT permission, invalidate every later AGPL grant, or resolve every historical revision's licensing. SR_team separately added an AGPL license and declaration in `eee5020eabc5a41b03bb3f3c703bb3fd71f4ed18` and made extensive original contributions. Do not replace AGPL metadata solely on the basis of this discrepancy.

### Sweep's own contributions have a separate permission question

The inherited Sweep snapshot has no LICENSE file or package `license` declaration. The reviewed public [Sweep manifest](https://github.com/sweepai/vscode-nes/blob/main/package.json) and repository likewise did not supply an MIT grant. GitHub explains that [a public repository without a license does not grant general reuse rights](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

The port's existing GPL obligations do not, by themselves, prove that Sweep licensed all independently authored extension code under GPL/AGPL. A downstream license label cannot cure a missing grant from another rightsholder. Permission to retain that code needs its own evidence or replacement.

### Public formats can remain implementation targets

The U.S. Copyright Office distinguishes [program expression from functional aspects such as algorithms and system design](https://www.copyright.gov/circs/circ61.pdf). This supports independently implementing the same functionality; it is not a categorical finding that every API declaration or data structure is unprotected. [Derivative-work guidance](https://www.copyright.gov/circs/circ14.pdf) explains why new contributions do not erase rights in preexisting material.

The [official Zeta 2.1 model card](https://huggingface.co/zed-industries/zeta-2.1) documents suffix/prefix/middle ordering and numbered markers, and identifies Apache-2.0 licensing. A new prompt builder/parser can target that documented format without porting the disputed implementation. Field names, marker spelling, ordinary constants, and interface compatibility alone are not findings of infringement.

## Proposed sequence for an MIT version

1. Freeze this audit's historical sources and define behavior requirements independent of the inherited implementation. Preserve the current AGPL-labelled history and releases as historical artifacts.
2. Establish a cleared runtime core: review the local Python/model service, managed provisioning, proto, continuation and observability work; record origins and third-party notices. Use a reviewed neutral interface for its editor-facing inputs and outputs.
3. Independently implement the editor/provider and context/history layers from VS Code APIs and behavioral requirements. Preserve existing feature parity unless a separate product decision removes a feature.
4. Independently implement the Zeta model adapter from public model documentation and tests derived from format requirements. Replace extracted helpers and inherited request/context orchestration. Reintegrate cleared local enhancements.
5. Replace/clear branding, preview rendering, status/rules/configuration glue, inherited tests and copied prose. Regenerate bindings/build metadata where appropriate.
6. Audit the resulting source tree and built distribution for copied expression, missing notices, retained upstream blobs, generated code and model/runtime terms. Mechanical similarity checks support this review; zero exact matches alone do not prove clearance.
7. Once ownership and replacement evidence support it, add the MIT grant for the cleared new version, accurate attribution/third-party notices, and updated package/repository metadata. Existing valid licenses already granted on earlier versions are not retroactively revoked.

A separate new repository/release snapshot can make the provenance boundary easier to communicate. Deleting Git history is not required to erase a supposed permanent license taint, and retaining history does not make the old commits MIT. Do not rewrite history or change the current license as a shortcut.

Where feasible, have an implementation author who has not read the disputed source work from a neutral functional specification, and retain those records. After this audit the current agents have seen disputed source; this session is not a source-isolated clean-room implementation. Independent authorship is a question of evidence, not an automatic consequence of rewriting with an AI tool or changing names.

Alternatively, written permissions covering the relevant Zed, Sweep contributor, SR_team and other contributor material can reduce or avoid replacement work. The exact rightsholders and coverage would have to be established; no contacts, permissions requests or external writes were made during this audit.
