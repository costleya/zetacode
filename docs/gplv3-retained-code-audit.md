# Retained-code audit for a GPLv3 release

Target: `3de40ca6d2fe6574e57e631dcc261b7f3bedcbc7`, audited 2026-10-27. This narrows the earlier MIT-oriented file inventory to a GPLv3 release without retained AGPL-only contributions. It does not change application source or licensing metadata. Choosing `GPL-3.0-only` versus `GPL-3.0-or-later` for a later release is outside this audit.

## Result and decision rule

The earlier **27 inherited source files** figure is not a rewrite requirement. Many inherited regions are declarations, defaults, ordinary adapters, or demonstrably related to the GPL-licensed Zed source. Mixed files contain local implementation that can remain. The engineering task is to replace specific retained implementations whose GPL-compatible permission has not been established, while preserving interfaces and independently owned additions.

There are two different reasons for flagging code:

1. **SR_team or other contributors' retained AGPL implementation:** a GPLv3 release without AGPL obligations needs another applicable grant, removal, or independent replacement of that implementation.
2. **Sweep's retained custom implementation:** the audited source did not supply an explicit grant for Sweep's own additions. These candidates are conditional on that unresolved permission question. A grant covering them could eliminate their replacement work. A commit titled “based on Zed” does not establish that every extension method was copied from GPL code.

The statuses in the accompanying region map mean:

- **KEEP:** no replacement indicated by this source/provenance audit: GPL-source correspondence, independently introduced local implementation, functional interface, or sufficiently routine/trivial glue. This is not a blanket legal clearance of every surrounding file or third-party input.
- **REPLACE_CANDIDATE:** a concrete retained implementation or prose region worth independently replacing if no suitable permission is available. It is an engineering boundary, not a ruling that every line is protected expression.
- **REVIEW:** materially mixed implementation or insufficient evidence to choose a smaller replacement/retention boundary. The report identifies the uncertainty rather than automatically rewriting its whole containing file.

Copyright in functional ideas and copyright in their source expression are different questions. A standard algorithm is not automatically off limits, and calling an algorithm “standard” does not automatically clear a copied implementation. The [Copyright Office's software guidance](https://www.copyright.gov/circs/circ61.pdf) supplies this distinction; this engineering audit does not adjudicate it.
