## Decision

The mechanical mixed classification substantially overstates the test-port problem. Of its 31 paths:

- **16 are portable whole as independently introduced or substantively rewritten local tests/fixtures.** Their shared earlier lines are imports, structural API/data declarations, braces, or ordinary test boilerplate, not inherited expressive test bodies.
- **1 additional whole file (`jump-edit-manager.test.ts`) is portable as local rewritten tests plus a retained routine API fixture.** It must not be described as entirely Aaron-authored.
- **1 shared mock (`setup-vscode-mock.ts`) is portable as low-expression API scaffolding after deleting/rewording its copied explanatory comment.** It is genuinely descended from SR source; migration did not independently author it.
- **4 files should start from the accepted Sweep test version**, with runner/import modernization and the specified local additions.
- **8 intervening-fork test files should not be ported as current files.** Their substantive bodies are inherited; local changes were runner migration, formatting, name changes or removal of other inherited tests.
- **1 Zeta parser test file supplies only identified local test additions**, with its simple DTO-building fixture treated separately.

This is a source-backed engineering decision under the same routine API/type/helper treatment as the accepted audit. It does not certify third-party rights outside the examined history or require rebuilding every standard mock/coordinate helper merely because its first Git author was SR_team.

## The 52 whole-file ports: generated/source input review

I inspected `docs/rebuild-ported-files.json` (52 paths), generation scripts/headers/proto, stubs, and their introducing history. No evidence of a substantive intervening-fork implementation hidden inside those generated outputs was found.

- **Protobuf/gRPC Python files:** `completion_pb2.py`, `.pyi`, `completion_pb2_grpc.py`, `.pyi` are ordinary generated bindings from local `79ea684` protocol work. `completion.proto` defines the local streaming completion/health service, with functional request/result fields. Generated headers identify compiler/plugin versions; they are not evidence that Aaron authored the generator templates. Preserve generated headers and normal dependency notices; do not import the old project's AGPL label merely because a compiler emitted the file. Regeneration from the accepted local schema is the preferred reproducibility check, not a prerequisite for using the checked-in generated source during reconstruction.
- **TypeScript gRPC output:** `src/api/generated/completion.ts` is not among the 52 whole-file ports, but the mechanically mixed classification is likewise misleading for this output. Its `protoc-gen-ts_proto` header and `79ea684` introducing patch establish ordinary generation from the same local schema. Common message fields/template fragments found by copy-aware blame are not a substantive SR adapter implementation. It is portable/generated, subject to the normal schema/generator/runtime notices and regeneration check.
- **MLX typing stubs:** the four small `.pyi` files were added in Aaron `7302d01`; they are protocol/signature/type declarations (49 lines total), not copied MLX inference bodies. Preserve necessary external API shapes; no material inherited-code replacement is indicated.
- **Lockfiles:** `pnpm-lock.yaml`/`uv.lock` are generated dependency resolutions. Copying them does not relicense downloaded packages; ordinary dependency-license/notice review remains necessary for distribution. No full transitive notice audit was performed here.
- **Icon font generator:** `tools/build-icon-font.mjs` is local source, not a font/artwork clearance. It reads **`assets/nesweep-glyph.svg` and `nesweep-load-{1,2,3,4}.svg`** (reference lines 53, 107) and writes `assets/nesweep-icons.woff2` (line 300). Its output inherits its actual drawing inputs; use cleared replacement SVG inputs before generating a font. This is the concrete generated-asset dependency requiring attention, rather than a reason to discard the generator. Neither PNG nor WOFF2 is in the 52-file whole-source port list.

Generated/runtime packages retain their own licensing terms. This review finds no generated-code prohibition or source-provenance blocker in the 52 ports; it does not certify that all third-party notices are complete or that all outputs have been regenerated byte-for-byte.
