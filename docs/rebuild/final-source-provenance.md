## Source classes in the reconstruction

### 1. Retained bodies from the accepted Sweep base

The reconstruction starts from the complete `fa52a26` tree. Existing Sweep bodies are retained from that revision where the reconstruction does not replace or extend the relevant behavior. For modified files, the baseline body is the `fa52a26` version; later current-main files are not used as the starting point. The accepted-baseline and historical origin analysis is summarized in [`port-manifest.md`](port-manifest.md), with detailed movement-aware line regions in [`gplv3-origin-regions.json`](../gplv3-origin-regions.json).

This is the chosen baseline for this rebuild. `ca153cb` is only the first middle-fork commit; it is not the source base. The later historical snapshot `cddda93` is useful for understanding what the fork inherited, but it is not the content source for the rebuild.

### 2. Fifty-two reviewed whole-file local ports

[`rebuild-ported-files.json`](../rebuild-ported-files.json) is the 52-path allowlist. It covers local implementation, server/runtime support, generated bindings, tests/fixtures, typing support, and build/package scaffolding; it does not mean 52 production modules or 52 files with final content hashes. The list is the scoped whole-file port set after review, not a raw file-creation list. It omits three machine-local `.codex` configuration/state paths that appeared in the earlier 55-path mechanical candidate group.

[`test-provenance.md`](test-provenance.md) records the test/fixture and generated-code review. In particular, generated outputs are evaluated against their schema or generator inputs, and ordinary test API DTOs/fixtures are distinguished from inherited test scenarios. The list and review remain evidence of port decisions; they do not substitute for the final integrated-tree pin below.

### 5. Generated inputs, artwork, and tests

- **gRPC protocol:** `tools/zeta-server/src/proto/completion.proto` is the local schema input. The Python and TypeScript protobuf/gRPC bindings are generated from it. Keep the schema, generation script, generated outputs, and runtime package together; record generator/runtime versions and normal third-party notices. Generated code's template boilerplate is not evidence that the generator itself was authored locally.
- **New N artwork and font:** the rebuild's eight new assets are the N monogram, static mark, and status/loading glyph/frame set. The font generator `tools/build-icon-font.mjs` consumes the new glyph SVG and `nesweep-load-1.svg` through `nesweep-load-4.svg` and emits `assets/nesweep-icons.ttf` directly. The generated TTF replaced a WOFF2 wrapper that failed OTS validation. The artwork inputs are newly created for this rebuild; do not substitute the historical middle-fork art. Their current hashes are recorded in the JSON companion. The old `assets/sweep_ai.svg`, `assets/sweep-square.png`, and `assets/sweep-icons.woff2` are removed from the package source as orphaned legacy assets.
- **Dependency lockfiles and stubs:** `pnpm-lock.yaml` and `tools/zeta-server/uv.lock` record dependency resolutions; MLX `.pyi` files are API typing declarations. Keep upstream dependency notices; this source index is not a complete dependency SBOM.
- **Tests:** use [`test-provenance.md`](test-provenance.md) for whole local suites, retained Sweep tests, and excluded inherited suites. The 52-path allowlist includes tests and fixtures, but test cases from mixed suites are selected/rebuilt according to that report, not copied wholesale by file path.
- **Installed behavior reference:** [`bundle-comparison.md`](bundle-comparison.md) records the local source build's byte-equivalence to the installed JS bundle after build-root path normalization. [`installed-provenance.md`](installed-provenance.md) distinguishes the installed extension payload from the older already-running helper service. Neither document pins the final reconstruction source tree.
