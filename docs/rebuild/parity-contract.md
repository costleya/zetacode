## Runtime prerequisites and controls

- Managed model runtime requires Apple Silicon macOS 14+ with Metal; the locked Python environment is Python `>=3.13,<3.14` and `mlx-lm==0.32.2` (`tools/zeta-server/pyproject.toml`). `uv` must already be installed; NESweep does not install it. Initial setup needs network access to resolve locked dependencies and Hugging Face weights; README budgets roughly 9 GB for weights/runtime/cache.
- Expected model repositories are `NexVeridian/zeta-2.1-4bit` and `mlx-community/Qwen2.5-Coder-7B-Instruct-4bit`; server IDs are `zeta-2.1` and `qwen2.5-coder-7b-instruct`. Set/record `HF_HOME` and any `ZETA_MODEL`/`QWEN_MODEL` overrides. Managed startup uses a private Unix socket, no TCP listener. Preserve/record `MLX_METAL_RESIDENCY_REFRESH_INTERVAL_MS` (default 1000; 0 disables refresh/wired-memory setup).
- For a developer-managed checkout server, docs give `uv sync --locked --project tools/zeta-server` followed by `tools/zeta-server/run.sh --socket-path "/tmp/nesweep-$(id -u)/developer.sock"`. This is not extension configuration; extension provisioning owns its own global-storage runtime and socket.
- Do not start a server or invoke MLX/GPU until the parent authorizes benchmark execution. `ps` inspection was denied by the managed sandbox during this read-only audit, so this audit does not independently attest which model processes are currently running.
